Glossary (from CONTEXT.md)

Htmx request

Any request carrying HX-Request. Boosted is a subtype, not a synonym.

Partial / Fragment / Full page

Partial = fragment-only wire response. Fragment = Blade @fragment mechanism via fragment()/fragmentIf(). Full page = complete document for non-htmx or history-restore.

Trigger

Client event fired after swap via the single v4 HX-Trigger header (JSON detail + target key).

Non-goals

No package routes, no migrations, no package translations. App owns endpoints and strings.

Phase 1 · Request / response core

Build the wire contract first — everything else demos it.First

Files

  • src/HtmxManager.php (new) — detection: isHtmx/isPartial/isBoosted/isHistoryRestore/source/target/requestType.
  • src/Htmx.php (replace stub) — response builder: 9 header methods + 4 aliases.

  • workbench/routes/web.php + one Blade page with @fragment('rows') demo.

Acceptance

  • HX-Source/HX-Target parsed as tag#id; HX-Request-Type: partial drives isPartial().
  • History-restore request returns full page even with HX-Request present.
  • 422 error fragment swaps into target in workbench demo.
  • view('page')->fragmentIf(htmx()->isPartial(), 'rows') proven by a failing-then-passing Pest test.
Request semantics to encode 
isHtmx()          = HX-Request present
isPartial()       = isHtmx AND HX-Request-Type == partial AND NOT history-restore
isBoosted()       = HX-Boosted present → defaults to full page
isHistoryRestore()= HX-History-Restore-Request present → full page
source()/target() = HX-Source / HX-Target (tag#id format)

Dependencies & risks

  • OOB swaps after main content in v4 — keep swaps independent; document.
  • fetch() replaces XHR — no progress/abort XHR events; timeout now defaults 60s.
  • from:/target: selectors with spaces/commas need single quotes — upgrade-check must flag old paren syntax.
  • Compat matrix (PHP ^8.3, Illuminate ^12||^13, Testbench ^10||^11) checked by composer test (analyse + lint + type-coverage + Pest).
