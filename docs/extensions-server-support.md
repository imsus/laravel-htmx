# htmx 4 Extensions — Server-Contract Survey

Sources: primary only — each extension's doc page under `https://four.htmx.org/extensions/<slug>`, read 2026-09-04. Every wire-contract claim cites its page. This repo vendors `hx-history-cache` + `hx-prompt` (plus `hx-ptag`) under `public/` (see `public/hx-history-cache.js`, `public/hx-prompt.js`, `public/hx-ptag.js`).

## Per-extension detail (server's view)

- **`hx-multipart`** ([doc](https://four.htmx.org/extensions/hx-multipart)): envelope is a normal HTTP response (`Content-Type: multipart/mixed; boundary=…`); parts are header/body pairs with NO status line (`Content-Type` + optional `HX-*` per part, blank line, body, next boundary, `--…--` terminator). Part bodies arrive in wire order; `multipart/mixed` serialises swaps in order while `multipart/parallel` lets later parts swap without waiting. Non-HTML part types (`application/json`, audio/video/octet-stream) are deliverable in the same envelope for custom `htmx:multipart:before:part` handling.
- **`hx-sse`** ([doc](https://four.htmx.org/extensions/hx-sse)): standard SSE framing over any htmx HTTP method (fetch/ReadableStream, not EventSource). `data:` payloads are HTML swapped per the request's `hx-target`/`hx-swap`/`hx-select` (plus `hx-swap-oob`/`<hx-partial>` multi-updates); `event:` payloads become DOM events (`event.detail = {data, id}`). `id:`/`Last-Event-ID` replay is server-driven (client does not dedupe). Laravel already documents event streams ([linked from the doc](https://four.htmx.org/extensions/hx-sse)), so the adapter needs at most a thin `eventStream()`/partial helper, not a new protocol.
- **`hx-prompt`** ([doc](https://four.htmx.org/extensions/hx-prompt)): `HX-Prompt` is a regular request header — `$request->header('HX-Prompt')`. No response contract.
- **`hx-preload`** ([doc](https://four.htmx.org/extensions/hx-preload)): `HX-Preloaded: true` marks speculative GETs — useful only to distinguish them in logs/rate-limits; no response contract.
- **`hx-ptag`** ([doc](https://four.htmx.org/extensions/hx-ptag)): HTTP-ETag-shaped but per-element and app-defined: compare incoming `HX-PTag` with current version, return `304` (no body) when unchanged, else render + stamp outgoing `HX-PTag`. Timestamp tags double as "since" cursors.
- **`hx-download`** ([doc](https://four.htmx.org/extensions/hx-download)): three server patterns — direct file + `Content-Disposition: attachment`, or `HX-Download: <url>` + normal HTML swap. Filename from `Content-Disposition`, progress % from `Content-Length`.
- **`hx-csp`** ([doc](https://four.htmx.org/extensions/hx-csp)): the only extension demanding per-request server cryptography (nonces), response headers on full AND partial responses, Blade stamping of `hx-nonce` on every htmx element, escaping discipline (entity-escaping does NOT protect `hx-on:`/`js:`/trigger-filter JS contexts — keep user data in `data-*`), and cache `Vary` handling. Includes the Laravel Blade example (`hx-nonce="{{ csp_nonce() }}"`) verbatim.

## What this package implements

Shipped (exact seams as the detection core + header builder): `ptag` request accessor (macro/helper/facade), `ptag($tag)` response header (builder/macro) for the 304-skip loop, `prompt()` request accessor for `HX-Prompt` answers, `isPreloaded()` detector for `HX-Preloaded: true`, `Htmx::eventStream()` for `hx-sse` framing (`text/event-stream` + `data:`/`event:`/`id:`/`retry:` blocks), `download($url)` response header (builder/macro) for the `HX-Download` secondary-fetch pattern, `assets.core` switch emitting the vendored `htmax.js` max build alone instead of core-plus-extensions, vendored `hx-ptag.js` with SRI + allowlist entry, and a workbench polling demo.

## htmax bundle mode

`htmax.js` (vendored under `public/`) is htmx plus 11 extensions — `hx-sse`, `hx-ws`, `hx-preload`, `hx-browser-indicator`, `hx-download`, `hx-pending`, `hx-targets`, `hx-live`, `hx-upsert`, `hx-alpine-compat`, `hx-history-cache` — in one file, auto-available with no per-extension script tags ([bundle doc](https://four.htmx.org/docs/htmax)). Flip `assets.core` to `'htmax.js'` and `<x-htmx::scripts />` emits only that file: the standalone extension scripts stay out, since loading them alongside would register twice.

Server-side, only the same four bundle members ever need anything (see table above): `hx-sse` → `Htmx::eventStream()`; `hx-download` → `download($url)` or a plain `response()->download()` with `Content-Disposition: attachment`; `hx-preload` → `isPreloaded()`; `hx-ws` → a real socket server (still out of scope). The other seven are client-only. Note the bundle ships `history-cache` disabled by default — opt in with `'historyCache' => ['disable' => false]` under `client` config (merged verbatim into the `htmx-config` meta payload), and keep `hx-history="false"` for pages that must never cache.

Deferred (documented follow-ups, not in scope): `hx-csp` nonce/CSP pipeline (largest surface, needs its own design), `hx-multipart` response builder. Out of scope: `hx-ws` (needs a socket server) and all client-only extensions (`hx-live`, `hx-pending`, `hx-browser-indicator`, `hx-history-cache`, `hx-head`, `hx-upsert`, `hx-targets`, `htmx-2-compat`, `hx-alpine-compat`).
